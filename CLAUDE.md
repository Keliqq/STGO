# Shop Titans Gear Optimizer

## Цель
Браузерное приложение подбирает экипировку, стихии и духов для героев Shop Titans:
1. под конкретную локацию (квест + сложность), с учётом урона босса, порогов защиты и стихийного барьера;
2. «универсальный» набор, лучший в среднем по выбранной группе локаций.

## Архитектура: SPA без сервера
- Всё выполняется в браузере. Никакого backend, никаких API-ключей, никаких прокси.
- Сборка: Vite + TypeScript (strict) + React. Тесты: Vitest. CSV: PapaParse. Кэш: IndexedDB (idb-keyval).
  Тяжёлые расчёты (симуляция, оптимизатор) — в Web Worker (Comlink), чтобы UI не зависал.
- Результат сборки — статичные файлы в dist/, деплой на GitHub Pages (workflow в .github/workflows).
  Пути относительные (base: './'), чтобы работало из любой папки.
- Данные пользователя (герои, инвентарь, настройки) хранятся только в его браузере (IndexedDB) + экспорт/импорт JSON.

## Актуальность данных
- При старте приложение берёт данные из IndexedDB. Если кэш старше 24 ч (настройка в UI) — фоном перечитывает листы,
  валидирует схему, пересобирает модель и показывает «Данные обновлены: +N предметов, изменено M».
- Если таблица недоступна или её структура изменилась — работаем на последнем рабочем кэше и показываем предупреждение.
- Первый запуск офлайн: в бандл кладётся снапшот данных (src/data/snapshot.json), сгенерированный при сборке.
- Кнопка «Обновить данные сейчас».

## Правила
- Логика игры — чистые функции в src/engine/ без зависимостей от DOM и React, покрыты тестами.
  Магические числа — только в src/engine/constants.ts с комментарием-источником.
- Если формула не подтверждена данными, помечай `// ASSUMPTION:` и вноси в docs/ASSUMPTIONS.md.
- В конце каждой сессии обнови docs/PROGRESS.md: что сделано, что дальше, известные проблемы.
- Интерфейс и ответы пользователю — по-русски.
