## Сессия 7 — 2026-10-09: цена промаха отсева и его исправление

### Задача
Отсев по quickScore терял лучший по симуляции вариант слота в 21,7 % случаев (26/120). Цель: промахи < 5 %, потеря win rate при промахе ≤ 1 п.п., время запуска ≤ 10 с.

### 1. Цена промаха (замер до)
Тот же набор из 120 случаев (20 герой+квест × 6 слотов, 15 вариантов слота, симуляция 300 прогонов, общий seed), новый тест `optimizer.prune.test.ts`. Метрика «промах» = лучший по симуляции вариант не попал в отсев.
- **Чистый top-K: 26/120 (21,7 %).**
- **Потеря win rate при промахе: медиана 0 п.п., max 0 п.п.** Все 26 промахов оказались «ничьими» — win rate отсеянного «лучшего» совпадал с лучшим из оставленного множества (в основном 0 % или 100 %: слот на исход боя не влиял). То есть 21,7 % — верхняя граница, реальный вред был ниже; но сам факт, что quickScore ранжирует ненадёжно, оставался.

### 2. Разбор промахов (что отсекалось)
- По слотам: относительно ровно, чуть больше слоты 3–5 (аксессуары): слот0:1 слот1:4 слот2:5 слот3:6 слот4:5 слот5:5.
- По типам: Spell:4, Rogue Hat:3, Meal:2, Gloves:2, Herbal Medicine:2, Amulet:2, Light Armor:2 и др.
- Признаки отсеянного «лучшего»: **вторичный стат — 12/26**, **связь стихии — 7/26**, встроенный камень — 3/26; щитов/тотемов/артефактов среди промахов не было. Вывод: quickScore недооценивает предметы с несколькими статами и со связью стихии (их синергию аналитическая оценка не видит).

### 3. Исправление (без раздувания бюджета симуляций)
`optimizer.ts → selectSlotCandidates` + правка `pruneSlot` + локальный поиск в `runOptimizer`:
- **Разнообразные кандидаты:** кроме top-K в отсев всегда попадают лучший по каждому измерению (ATK, DEF, HP, EVA, CRIT, величина стихии), лучший артефакт и лучший со связью стихии.
- **Адаптивный K:** если quickScore K-го и (K+5)-го различаются не более чем на `OPTIMIZER_K_ADAPT_TOL = 0,05` (полка плоская), K расширяется на 5 и дальше (A38).
- **Локальный поиск:** после координатного спуска для каждого слота симуляцией проверяются `OPTIMIZER_LOCAL_NEIGHBORS = 3` следующих по рангу quickScore кандидата.
Всё это — дешёвые вызовы quickScore + несколько симуляций в рамках прежнего бюджета `OPTIMIZER_SIM_BUDGET = 500`.

### 4. Замер после
- **Отсев с разнообразием и адаптивным K: 3/120 (2,5 %) — цель < 5 % выполнена.**
- **Потеря win rate при промахе: медиана 0 п.п., max 0 п.п.** (оставшиеся 3 промаха тоже «ничьи»).
- **Время:** полный прогон «3 героя + Argon, пул all T20 Legendary, босс с барьером» — **4,4–5,0 с, 496 симуляций** (в бюджете ≈10 с). Новый бенчмарк `optimizer.bench.test.ts` (таймаут теста поднят, чтобы не падал при параллельной нагрузке).

## Сессия 6 — 2026-10-09: оптимизатор экипировки, инвентарь, «проверка на реальности»

### Решения по итогам сессии 5 — выполнены
- **Отсев только по рангу, K с запасом.** `quickScore` используется исключительно для отсева (top-K на слот, `OPTIMIZER_TOP_K = 10`, допустимый диапазон 8–12), финальный выбор — только симуляцией. **Проверка на 20 случаях** (случайные герой+квест, на каждый из 6 слотов 15 случайных вариантов, симуляция 300 прогонов с общим seed, K=10): лучший по симуляции вариант слота **не попал в топ-K в 26/120 случаев (21,7 %)** — тест выводит долю в лог (`optimizer.test.ts`). Промах отсева не фатален: финальный отбор и симуляционная доводка идут по всей памяти beam, а не только по отсеянному.
- **Бюджет симуляций и CRN.** `OPTIMIZER_SIM_BUDGET = 500` вызовов `simulateTeam` (по 2000 прогонов) на запуск; все кандидаты сравниваются на **общем seed** (`OPTIMIZER_CRN_SEED`) — common random numbers, шум не решает исход близких наборов. Реальный прогон «3 героя + Argon, пул all T20 Legendary, квест-босс с барьером»: **345 симуляций за 3,2 с** (в бюджете ≈10 с), прогресс и отмена работают.
- **Проверка на реальности.** В UI можно отметить «этот отряд проходит / не проходит квест X»; рядом показывается предсказание симуляции (win rate на момент отметки). Отметки хранятся в IndexedDB (`realityChecks.ts`) и копятся как набор калибровки; считается доля совпадений («проходит» ↔ win rate ≥ 50 %).

### Что сделано
- **`src/engine/optimizer.ts`** — чистый движок подбора (без DOM, работает в воркере):
  · вход: 1–3 героя + чемпион (ранг), режим `quest` / `universal` (список локаций с весами; цель — средзвешенный win rate, опция `robust` — максимум минимума, отдельно показывается худшая локация), пул `owned`/`all`, ограничения (max тир, max качество, max тир камней, доступные духи, Душа, уровень);
  · отсев: для каждого слота перебор предметов → камней (только стихия героя; Any/Spellblade — любой) → духов, top-K по quickScore в контексте текущего набора;
  · координатный спуск по quickScore: сначала по ролям (танк — DEF до порога 75% и угроза, ДД — урон+выживаемость, A37), затем совместная доводка;
  · финал: beam-10 кандидатов + симуляционная доводка по слотам в пределах бюджета; цель `quest` — win rate, при равенстве меньше раундов;
  · барьер не пробит → симуляция штрафует (A9) + предупреждение в результат;
  · объяснения: для каждого изменённого слота — на сколько п.п. упал бы win rate, вернуть старую вещь (симуляция с тем же seed);
  · ограничения: типы по слотам класса, ≤1 артефакта на героя, owned — только предметы/камни/духи из инвентаря; детерминизм при фиксированном seed.
- **Worker/клиент**: `optimize(data, input, onProgress)` в `engine.worker.ts` (отмена — частичный результат с флагом); в `client.ts` — кэш результатов в IndexedDB по хешу входа (FNV-1a от данных+настроек, до 50 записей, отменённые не кэшируются).
- **`src/data/inventory.ts`** — инвентарь пользователя: CSV/ручной ввод (`type,name,quality` = item/stone/spirit, PapaParse), имена сверяются с таблицей (опечатки — в `unknown`), повтор предмета оставляет лучшее качество; IndexedDB + слияние.
- **`src/data/realityChecks.ts`** — отметки «проходит/не проходит» (одна на пару «квест+отряд», замена старой), `agreement()` — доля совпадений с симуляцией.
- **Страница «Подбор»** (`/optimize`, ссылка в шапке): отряд (до 3 + чемпион и ранг), цель (квест или universal: сложность/тип/локации/robust), пул и ограничения, редактор инвентаря (текст/CSV-файл), прогресс-бар симуляций и отмена, результат: win rate по локациям, худшая локация, статус барьера, по слотам — иконки и «+N п.п.» отдачи замены, блок «Проверка на реальности» с списком отметок.
