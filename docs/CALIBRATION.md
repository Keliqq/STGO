# Калибровка симуляции по отметкам «проходит / не проходит в игре»

**Статус: данных нет — отчёт ещё не считался.**

Страница генерируется командой `npm run calibrate` по файлу `fixtures/reality.json`
(экспорт со страницы «Данные»: резервная копия JSON — герои + отметки). Пока отметок в проекте 0,
здесь только описание того, что появится в отчёте.

## Как получить отчёт

1. Проведите бой в игре и отметьте его на странице «Подбор» — кнопками «проходит» / «не проходит»
   (рядом показано предсказание симуляции на момент отметки).
2. На «Данных» посмотрите блок **«Точность модели»** (N боёв, доля совпадений, дата калибровки)
   и выгрузите «Экспорт JSON».
3. Положите файл как `fixtures/reality.json` и запустите:

   ```bash
   npm run calibrate
   ```

   Флаги: `--file <путь>`, `--runs <прогонов на отметку>` (по умолчанию 2000), `--no-tune` (только метрики),
   `--max-knobs <2–3>`, `--no-reference` (считать базу статов моделью роста, а не эталоном экспорта).

## Что будет в отчёте

| Раздел | Содержание |
|---|---|
| Что считалось | источник порогов защиты, источник героев, способ расчёта базы статов, оговорки (ранг чемпиона, уровень) |
| 1. Метрики | N боёв, доля верных при пороге win rate 50 %, **Brier score** (пересчёт сейчас и win rate в момент отметки), средний предсказанный win rate, смещение |
| 2. Где ошибаемся | разрезы по классам, героям, квестам, сложности, обычный/босс, экстриму и барьеру — с числом промахов в каждую сторону |
| 3. Чувствительность к допущениям | 24 варианта `MODEL_VARIANTS` (множители качества, сродство, база HP, крит врага, AoE, порядок ходов, кривая защиты, барьер, режим крита по отрицательному EVA) — Δ Brier, Δ согласия и ошибка сверки статов по `fixtures/heroes.txt` |
| 4. Подгонка параметров (до / после) | какие 2–3 параметра сдвинуты, на сколько, что стало с долей верных, Brier и сверкой статов |
| 5. Предсказания по отметкам | построчная таблица: квест, отряд, что было в игре, win rate сейчас и в момент отметки, верно/нет |

## Правила подгонки (почему параметров мало)

- Крутим **не больше 2–3 самых влиятельных** параметров (`--max-knobs`): на десятках отметок больше —
  это уже подгонка под выборку, а не калибровка.
- **Сверку статов ломать нельзя:** `fixtureStatRms` по `fixtures/heroes.txt` не может ухудшиться больше чем
  на `FIXTURE_RMS_GUARD = 0.5 п.п.` по ATK/DEF/HP относительно базовой модели — ход за пределами допуска
  отклоняется, и это видно в логе.
- Подгонка **пишет отчёт**, а не правит `constants.ts`: смена значения по умолчанию — отдельное решение
  с обновлением `docs/ASSUMPTIONS.md` (A57) и `docs/PROGRESS.md` («Было / Стало»).
