# Допущения и проверенные факты

Формат: **ID — утверждение** · статус (✅ проверено / ⚠️ допущение / ❓ неизвестно) · на чём основано. В коде допущения помечаются `// ASSUMPTION: A<n>`.

## A1 — Загрузка данных из браузера без сервера · ✅ проверено 2026-10-09

**Как проверял.** Страница `docs/cors-probe.html` запускалась с dev-сервера Vite (`http://localhost:5179`) в Chromium (Playwright). Чтобы повторить: скопировать файл в `public/`, запустить `npm run dev` и открыть `/cors-probe.html`.

| Вариант | URL | Результат из браузера |
|---|---|---|
| gviz CSV | `/gviz/tq?tqx=out:csv&sheet=QUESTS` | ✅ 200, `response.type = "cors"`, `text/csv` |
| **export CSV** | `/export?format=csv&gid=<gid>` | ✅ 200, `cors`. Редирект на `*.googleusercontent.com`, fetch проходит его прозрачно; BLUEPRINTS ≈ 1,1 МБ |
| gviz JSONP | `/gviz/tq?sheet=…&tqx=out:json;responseHandler:cb` | ✅ работает (183 строки) |
| pub CSV | `/pub?output=csv&gid=…` | ⚠️ отвечает 200 `cors`, содержимое не проверялось. Таблица, похоже, не «опубликована в интернете», так что на этот вариант не опираемся |

**Выбор: основной — `export?format=csv&gid=…`, запасной — gviz CSV по имени листа.**
Почему не gviz по умолчанию: gviz сам определяет тип каждой колонки и **выбрасывает значения «неосновного» типа**, а ещё склеивает строки-заголовки. Сравнение тех же листов (`npm run dump-sheets -- --gviz`):

| Лист | Непустых ячеек export → gviz | Что потеряно в gviz |
|---|---|---|
| BLUEPRINTS | 141 508 → 135 717 | ~5 800 ячеек |
| QUESTS | 2 611 → 2 532 | заголовки `Monster Health`, `Barrier …` и др. (198 → 183 строки) |
| QUEST LEVELS | 742 → 728 | **названия всех локаций** |
| CHAMPIONS | 789 → 602 | имена чемпионов, `Element`, Element Breakpoints |
| HEROES | 2 820 → 2 817 | заголовки групп |

Для «карточных» листов это фатально, поэтому gviz — только запасной вариант. Он нужен, если у листа поменяется gid: имя листа стабильнее. Минус export — нужен gid, сейчас они захардкожены в `src/data/fetchSheet.ts` (`SHEET_GIDS`). Если export вернёт HTML, `fetchSheet` выдаст понятную ошибку, и вызывающий код сможет переключиться на gviz.

## A4 — Единицы процентов · ✅

BLUEPRINTS: EVA/CRIT хранятся дробью (`0.05` = 5%). HEROES/CHAMPIONS: строки `30%`, `20% (+20%)`, где в скобках указан вклад врождённого навыка, уже учтённый (примечание на листе: «Hero stats listed take into account the hero's innate skill»). Нормализуем к дроби.

## A5 — Духи: складывание, навык «+», бонус сродства · ✅ / ⚠️

- ✅ **Навыки одинаковых духов складываются** (3 × Walrus = +15% HP). Сверка с fixtures/heroes.txt: без складывания RMS ошибки ATK 9,1% / DEF 5,9% / HP 13,5%, со складыванием — 2,8% / 2,1% / 8,0%.
- ✅ Описания духов в экспорте TitansDB совпадают с обычной (не «+») версией навыка.
- ⚠️ «+»-версия — когда `Spirit Affinity` предмета = навык духа (`SPIRIT_PLUS_RULE`), статы духа ×`SPIRIT_AFFINITY_MULTIPLIER` = 1.5. **Не проверено:** в фикстуре нет ни одного духа в предмете своего сродства.
- Связь «дух → навык» точная (ключ игры с playshoptitans.com), совпадает для всех 40 духов.

## A6 — Сродство стихии (Elemental Affinity) · ⚠️ различимо слабо

Камень стихии в предмете с подходящим сродством (`All` = любая) усиливается ×1.5 (`ELEMENT_AFFINITY_MULTIPLIER`); что именно усиливается — `AFFINITY_SCOPE`. Сверка (RMS ATK / DEF / HP при подобранной модели базы):

| Вариант | ATK | DEF | HP |
|---|---|---|---|
| без бонуса (×1) | 3,6% | 2,5% | 6,9% |
| ×1.5 только камень | 2,8% | 2,1% | 8,0% |
| **×1.5 камень и дух (выбрано)** | **2,2%** | **2,1%** | 9,4% |
| ×2 только камень | 2,2% | 2,3% | 9,4% |
| ×1.5 весь предмет | 5,1% | 5,4% | 10,9% |

ATK однозначно лучше с бонусом; пара Geomancer 26 (одинаковая база, у обоих Owl Wing Wand с камнем Water) сходится при «камень + дух ×1.5…1.7». HP предпочитает отсутствие бонуса, но HP-сверка зашумлена моделью базы (A8). **Величину стихии сродство не меняет** (у Нины, Ирвина, Денама, Рейнелла камни в предметах своего сродства, а стихия в экспорте = сумма камней).

## A7 — Множители качества · ✅ частично

Normal ×1, Superior ×1.25, Flawless ×1.5, Epic ×2, Legendary ×3 к ATK/DEF/HP.
- ✅ Legendary ×3 и Flawless ×1.5 — пример Combat Compendium (Wand of Midas 410 → 1230, Tarot Deck 530 → 795).
- ✅ Superior ×1.25 — пара Geomancer 26: у Вестии Superior броня, у Логарсона Normal, вычисленная база DEF 276,4 и 277 (при ×1.2 разошлась бы на 12).
- ⚠️ Epic ×2 в фикстуре есть (4 героя), отдельно не выделялся; ошибки у этих героев в пределах общей.
- ✅ **Статы камней и духов качеством не масштабируются** (компендиум: Tide даёт 38 ATK и Legendary-жезлу, и Flawless-колоде).
- Округление после множителя — `Math.round` (не проверено: разница ±0,5 тонет в шуме модели базы). Пример Mistpeak Bloom из статьи не годится — значения предмета с 2020 года изменились.

## A8 — База героя по уровню · ⚠️ модель + калибровка по экспорту

Статов по уровням нет ни в HEROES (одно значение на класс), ни в HERO LEVELS (XP и макс. тир) — перепроверено в сессии 3. Сторонних источников нет: на playshoptitans.com страниц героев нет, трекер shoptitans.dowob.dev требует входа. По словам игроков, прирост — своя таблица на класс и уровень, нелинейная (Reddit: «Dancer 1–12 ур. +1–3 HP за уровень, с 12-го +5–8»).

**Обратный счёт:** для каждого героя база = итог / (1 + Σ%) − Σ вкладов предметов − плоские прибавки. Затем МНК по относительной ошибке итогового стата; форма модели выбрана по ошибке leave-one-out (каждый герой предсказан моделью, подогнанной без него):

| Форма | ATK LOO | DEF LOO | HP LOO |
|---|---|---|---|
| база₁ × (1 + k·(L−1)) | 5,9% | 3,9% | 10,6% |
| **база₁ × (1 + k·(L−1)) + c·(L−1)** (выбрано) | **2,4%** | **2,4%** | 10,8% |
| + квадратичный член | 2,4% | 2,2% | 11,0% |
| рост по группе Fighter/Rogue/Spellcaster | 2,3–2,5% | 2,6% | 9,9–10,8% |

Итог (`HERO_LEVEL_STAT_GROWTH`, переподобрано в сессии 4 с учётом A27): ATK k = 0,232, c = 7,15; DEF k = 0,292, c = 4,95; HP k = 0,125, c = 1,2. Проверено только на уровнях 23–33.

**Пары одинаковых классов** (вычисленная база): Geomancer 26/26 — DEF 276/277, HP 145/143, ATK 646/613 (сходятся); Knight 23→26 — HP 178→237 (+20 за уровень); Berserker 25→30 — HP 300→364; Ninja 26→33 — HP 137→204; Dancer 25→28 — HP 162→162 (!); Druid 23→24 — HP 162→111 (!). Две последние пары противоречат любой монотонной модели — у HP есть неучтённый фактор (см. «Расхождения»).

**HP: цель ±3% не достигнута** (RMS 9,4%, максимум 26%). Поэтому для импортированных героев база берётся из эталона экспорта (`stats.ts → referenceBase`): пока уровень героя не изменился, расчёт для любой экипировки опирается на его собственную базу. Перекрёстная проверка: база Вестии предсказывает Логарсона (тот же класс и уровень, другие экипировка и навыки) с ошибкой ATK +1,5%, DEF −0,1%, HP +0,7% (тест требует ≤ 2%).

### Расхождения, которые не объяснены (константы под них не подгонялись)
- **HP — главная нерешённая задача.** Гладкая модель роста базы (A8) даёт RMS 9%: недобор у Берсеркеров (Эйми −13%, Брю −12%, Селена −8%), перебор у Джорди (+25%) и Ирвина (+13%). Гипотеза сессии 4 (семена в колонках 13–19) опровергнута (A28): это Σ ATK%/DEF% игры, семян в экспорте нет. Причина — своя нелинейная таблица роста HP на класс, которой нет ни в HEROES, ни в HERO LEVELS. **Цель «HP ±3% у 15+ героев без эталона» не достигнута**; для импортированных героев база по-прежнему берётся из эталона (`referenceBase`). Что закроет вопрос: статы «голых» героев 3–5 классов на разных уровнях с экрана игры.
- **Пара Druid 23/24** объяснилась A27: у Регаса Bear Spirit в Totem Pole удвоен (+15 HP), база HP Регаса и Хуана сравнялась (−1,8% / −4,2%).
- **Стихия: Селена 95/90, Джорди 180/150** — излишек не объяснён (A21). Totem-удвоение камня не подходит (дало бы 105 и 175). Кандидаты: духи Ox/Chimera дают +5 стихии (в фикстуре по одному носителю — не проверить). На статы не влияет (ступени навыков не меняются).
- Мелочь: уклонение/крит больше не расходятся.

## A9 — Семантика барьера · ⚠️ допущение

`Barrier Type` — список стихий, `Barrier Health` — число. Допущение: барьер пробивается, если суммарная величина стихии отряда в **любой** из перечисленных стихий ≥ `Barrier Health`. Не пробит — урон отряда сильно снижается. Точная механика (порог или пропорция, вклад чемпиона, «Any») в таблице не описана. Есть косвенные подсказки в SKILLS: `+50% party Element bonus VS Elemental Barriers`, `Can use any element, but only counts as N% against Elemental Barriers`.

## A10 — Пороги защиты квестов — внешний источник · ⚠️

В таблице их нет. Источник — https://stcentral-hub.github.io/posts/main-quests/: статичный HTML, `Access-Control-Allow-Origin: *`, значит, из браузера читается без прокси. Формат: на сложность `50% X · 70% 2X · 75% 6X` (DEF → снижение урона). Lost City of Gold там нет.
Лицензия **CC BY-NC-ND 4.0**. **Решение владельца (сессия 2):** в snapshot.json и в репозиторий не кладём. `src/data/breakpoints.ts` загружает страницу в рантайме из браузера (CORS `*` проверен в Chromium), разбирает её регулярками (без DOM — работает в воркере и в тестах) и кэширует в IndexedDB на 7 дней. В UI («Данные») показан источник со ссылкой и лицензией. Если страница недоступна и кэша нет — режим «без порогов» (`mode: 'noCaps'`) с предупреждением. Поэтому `scripts/build-breakpoints.ts` не делался. В тестах — самодельный HTML той же разметки с выдуманными числами.
Сопоставление: блок локации и следующий за ним блок босса, сложность — по `title`. Покрыто 112 из 138 квестов (все, кроме Lost City of Gold). HP монстров на сайте совпадает с таблицей во всех 112.

## A11 — Запуск dev-скриптов · ✅

`scripts/*.ts` запускаются напрямую `node` (встроенное снятие типов, Node ≥ 22.18; проверено на 24.15). От `tsx` отказался: он тянет `esbuild` с postinstall-скриптом, а npm блокирует такие скрипты (`allowScripts`). Ограничение: в скриптах нельзя `enum`/`namespace`/parameter properties, импорты только с расширением `.ts`.

## A12 — Безымянная колонка 4 в SKILLS — порог стихии для ступени навыка · ✅

Числа 10–170 у ступеней ≥ 2 — **величина стихии героя, с которой открывается ступень** (Common T2 10–20 … T4 150, Rare T4 160, Epic T4 170). ## A15 — Артефакты: предмет → навык · ✅ / ⚠️

Связь предмета с навыком `Type = Artifact` даёт playshoptitans.com (`skill_a_<uid>_name`); сопоставлены все 13 артефактов.
**Midas' Tragedy.** У Ring of Midas и Amulet of Midas одно имя навыка, в SKILLS две строки: +25% и +50% к статам LCOG-снаряжения. На странице предмета (playshoptitans.com, `__NEXT_DATA__`) описания навыка нет, но есть `chest`: Amulet — `goldcity2` (Opulent, T10), Ring — `goldcity3` (Platinum, T15). Решение: **Amulet → +25% (первая строка), Ring → +50% (вторая)** — по порядку строк и тиру. Сверка по Брю (Amulet of Midas + Opulent Cloak): после переподгонки базы (A27) различие +25% vs +50% по сумме квадратов ошибок ATK/DEF стало в пределах шума (тест требует лишь, чтобы +25% было не хуже +50%). Для Ring of Midas не проверено (в фикстуре нет). В `build.ts` общее правило: если у нескольких предметов одно имя навыка артефакта, а в SKILLS несколько строк с этим именем, i-й по тиру предмет получает i-ю строку (тест в `build.test.ts`).

## A16 — «+N%» у EVA и CRIT · ✅

Парсер эффектов хранит число как в тексте (`+25% Crit Chance` → `{stat: 'crit', mode: 'pct', value: 25}`). Для ATK/DEF/HP это множитель. Для EVA/CRIT — прибавка к шансу в процентных пунктах, EVA/CRIT предметов прибавляются так же; для Critical Hit Damage — прибавка к множителю (`+100%`: ×2 → ×3). Сверка: крит и множитель крита совпали с экспортом у 17 из 18 героев, уклонение — у 16 из 18 (расхождения 1–2 п.п.).

## A17 — Мини-боссы · ❓

## A18 — Смена gid листа · ✅ проверено curl

`/htmlview` таблицы отдаёт список листов `{name, gid}` с CORS (`Access-Control-Allow-Origin` возвращает Origin запроса; проверено curl, в браузере этот путь ещё не срабатывал). Порядок загрузки листа (`fetchSheetResolved`): export по известному gid → не вышло — gid ищется заново через htmlview (имена там в другом регистре: `Blueprints`) → не вышло — gviz по имени. ## A20 — Иконки навыков и классов · ✅ / ⚠️

Имена файлов fankit — внутренние id игры, а не названия. Классы: имя без пробелов, кроме Samurai → `swordmaster`, Spellblade → `redmage`, Grandmaster → `mastermonk`, Fateweaver → `timekeeper` (42/42). Навыки: лидерские — `hero_<чемпион>leader<ступень>` (Reinhold → `king`, Tamas → `leather`), врождённые — `c_<базовый класс>`, духи — `i_<ключ>`, остальные — по имени любой ступени линейки (Warlord → War Master → `s_warmaster`). Найдено 463 из 621. Нет иконок у аурасонгов (файлы названы по предметам, а не по навыкам) и у части стат-навыков (`s_hp`, `s_megacrit`… по имени не угадать). Для них UI показывает заглушку.

## A21 — Стихия героя · ✅ / ⚠️

✅ Стихия героя = сумма камней **его** стихии (совпадает с экспортом у 16 из 18). Встроенный камень предмета (`Built-In Element`) входит в стихию, но его статы уже включены в статы предмета (компендиум: Mistpeak Bloom 163 + Eagle 16 = 179, Tide сверху не добавлен). ⚠️ Не проверено: что камни чужой стихии не считаются (в фикстуре все камни совпадают со стихией героя); камни Gold засчитываются любому герою (`GOLD_ELEMENT_COUNTS_FOR_ANY_HERO`, в фикстуре Gold нет). ❓ Излишек в экспорте: Селена 95 при 90 по камням, Джорди 180 при 150 — не объяснён (см. A8). Удвоение камня в Totem Pole (A27) не подходит: дало бы 105 и 175, а не 95/180. Кандидат: духи Ox/Chimera дают +5 стихии (в фикстуре по одному носителю — не проверить).

## A22 — Ступени навыков считает движок · ✅

TitansDB показывает в описании навыка **высшую** ступень (у всех 18 героев — 4-я, хотя 4-я требует промоушена, а все герои фикстуры — базовые классы). Поэтому импорт хранит линейку навыка, а ступень вычисляется из стихии героя (A12): `skillTierFor`. Имя навыка в экспорте бывает старым (`Mana Shield` = линейка `Magic Shield`) или id иконки (`S_scythemaster`). Порядок сопоставления: имя/имя любой ступени → id иконки fankit → описание (ключи «стат+число»).

## A24 — Душа Титана · ⚠️

Ступень врождённого навыка, требующая Души Титана, заменяет обычную ступень и не требует порога стихии. В фикстуре у всех `Душа Титана = No` — не проверено.

## A25 — «stats with <тип>» и «bonus from all items with <тип>» не усиливают DEF · ⚠️ выведено из сверки

Monk (`+100% stats with Ring`), Sorcerer (`+50% stats with Spell`): если применять бонус к DEF, вычисленная база DEF уходит в −35 и 43; без него — 194 и 232, в ряд с остальными. Druid (`+80% bonus from all items with Herbal Medicine…`) к HP применять нужно: без него база HP Druid 23 вдвое выше, чем у Druid 24. Похоже на фразу компендиума «навыки на оружие не влияют на вторичные статы», но точное правило («какой стат предмета вторичный») неизвестно. Параметр `TYPED_ITEM_BONUS_STATS = ['atk', 'hp']`. «Bonus from all items» без условия (Extended Warranty) усиливает все статы — как в компендиуме.

## A26 — Округление, зачарование, EVA/CRIT · ✅

- Итоговый стат — **отбрасывание дробной части**: в компендиуме 16307,55 показано как 16307 (в тексте «.5 rounds down», но пример — .55). Вклад предмета — обычное округление (2311,2 → 2311, 1103,7 → 1104).
- Камень и дух добавляют только те статы, которые у предмета уже есть (компендиум: «только два предмета с ATK»; на фикстуре альтернативы дают ошибку HP 16–17% против 7% и уводят базы ATK в минус).
- EVA/CRIT класса берутся как в HEROES, вместе с бонусом в скобках: у Ninja `30% (+20%)` карточка показывает +20/+20, хотя врождённый навык действует «until damaged» (сверка: Ирвин, Нина — точное совпадение).
- Контрольный пример компендиума (Geomancer Gong) воспроизводится точно: 16307 на числах статьи, 15797 на текущих данных таблицы (Wolf/Eagle теперь 19 ATK, Mistpeak Bloom 140 Normal, Extended Warranty при стихии 30 — 1-я ступень +20%). Тест `src/engine/stats.test.ts`.

## A27 — Portable Totem Pole удваивает навык вставленного в него духа · ✅ выведено из сверки

`Portable Totem Pole` (Idol, Spirit Affinity = Owl Wisdom) — в 7 героях фикстуры. Игра показывает **двойной** вклад навыка духа в этом слоте. Доказательства (колонка 18 = Σ ATK% игры, см. A28): у Эйми, Джорена, Денама, Регаса col18 на +5% больше суммы навыков (двойной Bear/Lion +5% ATK), у Джорди на +10% (двойной Chimera +10% ATK). То же по другим статам: EVA Джорена 37 (было 36, двойной Lion +1%), Рейнелла 49 (было 47, двойной Cat +2%); CritDmg Джорди 4,7 (было 4,6, двойной Chimera +10%). После удвоения col18/col19 совпадают с моделью у всех 18. Реализация: `stats.ts → activeSkills`, константа `SPIRIT_SKILL_DOUBLING_ITEMS`. Удваивается только навык, не статы духа и не камень (иначе стихия Джорди ушла бы в 175, а не 180).

## A28 — Колонки 13/18/19 экспорта — итоговые модификаторы игры, а не семена · ✅ проверено

Гипотеза сессии 4 (колонки 13–19 = Seed HP/ATK/DEF) **не подтвердилась**. Колонки 14–17 и блок 38–40 в фикстуре нули; колонки 18/19 — это Σ ATK% и Σ DEF% модификаторов, которые посчитала игра (с float-шумом: 224.942017 ≈ 225), колонка 13 — шанс пережить смертельный удар (у Денама 100 = навык «Crusader»). Дробные «кратные 5» значения — шум двоичной арифметики игры при накоплении процентов, а не семена. Модельный Σ ATK%/DEF% после A27 совпадает с col18/col19 у всех 18 героев (тест в `stats.fixture.test.ts`) — это самая точная проверка модели навыков. **Семян силы в экспорте TitansDB нет**, поэтому расхождение HP (A8) ими объяснить нельзя: рост HP по уровням — своя нелинейная таблица на класс, в данных отсутствует.
