# Допущения и проверенные факты

Формат: **ID — утверждение** · статус (✅ проверено / ⚠️ допущение / ❓ неизвестно) · на чём основано. В коде допущения помечаются `// ASSUMPTION: A<n>`.

## A1 — Загрузка данных из браузера без сервера · ✅ проверено 2026-10-09

**Как проверял.** Страница `docs/cors-probe.html` запускалась с dev-сервера Vite (`http://localhost:5179`) в Chromium (Playwright). Чтобы повторить: скопировать файл в `public/`, запустить `npm run dev` и открыть `/cors-probe.html`.

| Вариант | URL | Результат из браузера |
|---|---|---|
| gviz CSV | `/gviz/tq?tqx=out:csv&sheet=QUESTS` | ✅ 200, `response.type = "cors"`, `text/csv` |
| **export CSV** | `/export?format=csv&gid=<gid>` | ✅ 200, `cors`. Редирект на `*.googleusercontent.com`, fetch проходит его прозрачно; BLUEPRINTS ≈ 1,1 МБ |
| gviz JSONP | `/gviz/tq?sheet=…&tqx=out:json;responseHandler:cb` | ✅ работает (183 строки) |
| pub CSV | `/pub?output=csv&gid=…` | ⚠️ отвечает 200 `cors`, содержимое не проверялось. Таблица, похоже, не «опубликована в интернете», так что на этот вариант не опираемся |

**Выбор: основной — `export?format=csv&gid=…`, запасной — gviz CSV по имени листа.**
Почему не gviz по умолчанию: gviz сам определяет тип каждой колонки и **выбрасывает значения «неосновного» типа**, а ещё склеивает строки-заголовки. Сравнение тех же листов (`npm run dump-sheets -- --gviz`):

| Лист | Непустых ячеек export → gviz | Что потеряно в gviz |
|---|---|---|
| BLUEPRINTS | 141 508 → 135 717 | ~5 800 ячеек |
| QUESTS | 2 611 → 2 532 | заголовки `Monster Health`, `Barrier …` и др. (198 → 183 строки) |
| QUEST LEVELS | 742 → 728 | **названия всех локаций** |
| CHAMPIONS | 789 → 602 | имена чемпионов, `Element`, Element Breakpoints |
| HEROES | 2 820 → 2 817 | заголовки групп |

Для «карточных» листов это фатально, поэтому gviz — только запасной вариант. Он нужен, если у листа поменяется gid: имя листа стабильнее. Минус export — нужен gid, сейчас они захардкожены в `src/data/fetchSheet.ts` (`SHEET_GIDS`). Если export вернёт HTML, `fetchSheet` выдаст понятную ошибку, и вызывающий код сможет переключиться на gviz.

## A4 — Единицы процентов · ✅

BLUEPRINTS: EVA/CRIT хранятся дробью (`0.05` = 5%). HEROES/CHAMPIONS: строки `30%`, `20% (+20%)`, где в скобках указан вклад врождённого навыка, уже учтённый (примечание на листе: «Hero stats listed take into account the hero's innate skill»). Нормализуем к дроби.

## A5 — Версия навыка духа с «+» · ⚠️ допущение

У каждого духа два навыка: `Ram Robustness` и `Ram Robustness+`. Допущение: `+` срабатывает, когда дух вставлен в предмет, у которого `Spirit Affinity` равно имени навыка. В таблице это не сказано.
Сессия 2: в коде — `SPIRIT_PLUS_RULE = 'affinity'` и `SPIRIT_AFFINITY_MULTIPLIER = 1.5` (бонус статов духа при совпадении) в `src/engine/constants.ts`. Значение множителя — заглушка, подбирается в сессии 3 сверкой с экспортом героев.
Связь «дух → навык» теперь точная: ключ игры с playshoptitans.com (`Ram Spirit` → `skill = i_turtle` → `skill_i_turtle_name = Ram Robustness`), запасной вариант — первое слово имени. Совпадает для всех 40 духов.

## A6 — Эффект Elemental Affinity · ❓ неизвестно

В таблице нет правила, что даёт камень стихии в предмете с подходящим сродством (`All` = любая стихия). Сессия 2: параметр `ELEMENT_AFFINITY_MULTIPLIER = 1.5` в `constants.ts` (заглушка), подбирается в сессии 3.

## A7 — Множители качества · ⚠️ допущение (данных в таблице нет)

Распространённые в сообществе значения (по памяти, не проверены): Normal ×1, Superior ×1,25, Flawless ×1,5, Epic ×2, Legendary ×3 к базовым ATK/DEF/HP. Сессия 2: `QUALITY_MULTIPLIERS` в `constants.ts`; масштабируются ATK, DEF, HP и Mana Shield, EVA/CRIT — нет; округление `Math.round`. Всё это проверяется в сессии 3. Статы камней и духов в GameData хранятся только для Normal: как на них влияет качество, неизвестно.

## A8 — Статы в HEROES — это статы 1-го уровня · ⚠️ допущение

Лист даёт одно значение HP/ATK/DEF на класс, а HERO LEVELS — только XP и макс. тир. Прирост статов за уровень в таблице отсутствует. Вывести его обратным счётом из `fixtures/heroes.txt` (статы героя минус экипировка) в сессии 2 не удалось: этого файла нет в репозитории. Сейчас `HERO_LEVEL_STAT_GROWTH = 0` (статы не растут) — заглушка до калибровки в сессии 3.

## A9 — Семантика барьера · ⚠️ допущение

`Barrier Type` — список стихий, `Barrier Health` — число. Допущение: барьер пробивается, если суммарная величина стихии отряда в **любой** из перечисленных стихий ≥ `Barrier Health`. Не пробит — урон отряда сильно снижается. Точная механика (порог или пропорция, вклад чемпиона, «Any») в таблице не описана. Есть косвенные подсказки в SKILLS: `+50% party Element bonus VS Elemental Barriers`, `Can use any element, but only counts as N% against Elemental Barriers`.

## A10 — Пороги защиты квестов — внешний источник · ⚠️

В таблице их нет. Источник — https://stcentral-hub.github.io/posts/main-quests/: статичный HTML, `Access-Control-Allow-Origin: *`, значит, из браузера читается без прокси. Формат: на сложность `50% X · 70% 2X · 75% 6X` (DEF → снижение урона). Lost City of Gold там нет.
Лицензия **CC BY-NC-ND 4.0**. **Решение владельца (сессия 2):** в snapshot.json и в репозиторий не кладём. `src/data/breakpoints.ts` загружает страницу в рантайме из браузера (CORS `*` проверен в Chromium), разбирает её регулярками (без DOM — работает в воркере и в тестах) и кэширует в IndexedDB на 7 дней. В UI («Данные») показан источник со ссылкой и лицензией. Если страница недоступна и кэша нет — режим «без порогов» (`mode: 'noCaps'`) с предупреждением. Поэтому `scripts/build-breakpoints.ts` не делался. В тестах — самодельный HTML той же разметки с выдуманными числами.
Сопоставление: блок локации и следующий за ним блок босса, сложность — по `title`. Покрыто 112 из 138 квестов (все, кроме Lost City of Gold). HP монстров на сайте совпадает с таблицей во всех 112.

## A11 — Запуск dev-скриптов · ✅

`scripts/*.ts` запускаются напрямую `node` (встроенное снятие типов, Node ≥ 22.18; проверено на 24.15). От `tsx` отказался: он тянет `esbuild` с postinstall-скриптом, а npm блокирует такие скрипты (`allowScripts`). Ограничение: в скриптах нельзя `enum`/`namespace`/parameter properties, импорты только с расширением `.ts`.

## A16 — «+N%» у EVA и CRIT · ⚠️

Парсер эффектов хранит число как в тексте (`+25% Crit Chance` → `{stat: 'crit', mode: 'pct', value: 25}`). Для ATK/DEF/HP это множитель. Для EVA/CRIT — скорее всего прибавка к шансу в процентных пунктах, для Critical Hit Damage — прибавка к множителю (`+100%`: ×2 → ×3). Как трактовать — решает движок в сессии 3.

## A17 — Мини-боссы · ❓

В типе `Quest` есть поле `miniBosses`, но данных нет ни в таблице, ни на stcentral-hub: там только саб-локации обычных квестов (Elvenwood Glade…) и имя босса. Поле пока всегда пустое.

## A18 — Смена gid листа · ✅ проверено curl

`/htmlview` таблицы отдаёт список листов `{name, gid}` с CORS (`Access-Control-Allow-Origin` возвращает Origin запроса; проверено curl, в браузере этот путь ещё не срабатывал). Порядок загрузки листа (`fetchSheetResolved`): export по известному gid → не вышло — gid ищется заново через htmlview (имена там в другом регистре: `Blueprints`) → не вышло — gviz по имени. Обход пишется в статус данных. Найденные gid сохраняются вместе с кэшем.

## A19 — Навык `Quiver Bow Bonus` с Type `---` · ✅

Единственная строка SKILLS без типа: бонус колчана (`+30% bonus from all items with Bow`). Заведена как `Type = 'Other'`.

## A20 — Иконки навыков и классов · ✅ / ⚠️

Имена файлов fankit — внутренние id игры, а не названия. Классы: имя без пробелов, кроме Samurai → `swordmaster`, Spellblade → `redmage`, Grandmaster → `mastermonk`, Fateweaver → `timekeeper` (42/42). Навыки: лидерские — `hero_<чемпион>leader<ступень>` (Reinhold → `king`, Tamas → `leather`), врождённые — `c_<базовый класс>`, духи — `i_<ключ>`, остальные — по имени любой ступени линейки (Warlord → War Master → `s_warmaster`). Найдено 463 из 621. Нет иконок у аурасонгов (файлы названы по предметам, а не по навыкам) и у части стат-навыков (`s_hp`, `s_megacrit`… по имени не угадать). Для них UI показывает заглушку.
